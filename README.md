# Gallery

Gallery 是一个 Android 本地优先媒体库。用户通过系统目录选择器接入实体文件夹；媒体保持在原位置，`.gallery/` 保存可随硬盘移动、可供 Agent 理解的元数据和规则，本机 SQLite 只作为可重建索引。

当前一级界面只有三类：

- **相册**：照片和相册视频的纯净时间线。
- **图片 / 视频**：按真实目录分类的普通媒体相册。
- **漫画 / 动漫**：带作者、Tag、Series、搜索、排序和阅读/观看进度的作品库。

详细设计见 `Gallery_Project_Guide.md`，使用方法见 `docs/USER_GUIDE.md`，架构约束见 `docs/ARCHITECTURE.md`。

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

Debug APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。

我现在想做一个安卓端的本地媒体阅读器（目前应该只需要对于图片，视频的阅读能力），首先，对于本地文件，我希望用一种类似于steam库的管理模式，就是可以选择文件夹作为本地库（也就是不要管理乱七八糟的垃圾文件夹，只有我确认接入后，这个软件可以确保合理初始化和设置这个文件夹，后续只要接入这个移动介质，并且接入这个文件夹，这个软件就可以自己识别），后续发生在软件中的对于的所有文件分类，管理归纳之类的行为，都可以从文件夹对文件同时进行管理（举个例子，我在一个移动硬盘上从手机端分类了五个漫画，当我从电脑端打开的时候，希望也可以用一种合理的方式看见这个文件的存储逻辑，而不是底层文件乱糟糟的，只是手机软件上看起来分好类了），或者在电脑端同步做一个软件，用类似json或者什么文件的来管理分类和库中的具体文件，底层用更合理的存储逻辑
具体的
对于照片，有几类，一种是相片（这里包括视频），可以全部放到一起，可以正常按时间顺序看（视图层面）就可以，但是要注意相片格式，可能包含时间戳，位置之类的信息，同时也要支持动图（实况），类似于手机端常见的相册应用
对于其他图片，要支持自定义文件夹分类之类的，希望可以用一种合理的方式，而且希望可以套用子文件夹，对于一些文件，希望允许按漫画的阅读习惯浏览，并且可以添加标注/作者/内容之类的（类似于ehviewer的那种使用习惯），而且文件夹内导入我下载的漫画（一般是一个文件夹内按数字排序的很多图片）也可以自动识别，文件夹名和软件内名称不需要一致，但是软件内设置名称，文件夹可以用合理的方式保留原名称（更改后附带的标签和信息相关应该是保存在最开始提出的类似于steam库的那种管理模式里面
对于视频，要求和上述差不多，会存在的有电影，动画之类的（所以希望可以分系列，或者按作者分类，同时有可能标注第几集之类的）
对于已经存在在手机相册里的内容，因为我觉得手机自带的相册软件管理源文件很麻烦，希望也可以自动识别和管理（可以把源文件（不希望丢失任何信息）放入到设置好的库里，以合理的方式保存管理，但是正常情况下，因为这些文件本身可能不在库里，所以按理来说不应该识别，所以我觉得这个可能需要单独一个窗口
