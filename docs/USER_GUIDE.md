# Rem 0.0.2 使用说明

## 首次使用

1. 点击“选择文件夹”，通过 Android 系统目录选择器选择一个空目录或已有媒体目录。
2. Rem 会创建 `.gallery/`、`GALLERY_LIBRARY.md`、`.nomedia` 和 Schema v3；原媒体内容不会被改写。`.nomedia` 只阻止系统相册重复收录 Library 副本，不影响 Rem 扫描。旧 Library 会在接入或扫描时先备份元数据，再做兼容升级。
3. 扫描可识别 `JM/<数字 ID>/`、`JM/<数字 ID>.zip`、EhViewer 的 `<gid>-<title>/.ehviewer`、`eh/<gid>-<title>/`、Pixiv 的 `<illust_id>_pN` / `_ugoira…`，以及“系列目录/编号标题.cbz”。识别只读取目录与文件名，不需要站点账号，结果只是待确认建议。
4. 扫描完成后，新发现内容只进入 Inbox，不会同时混入正式的相册、图片 / 视频或漫画 / 动漫页面。可以长按单项选择“接受识别建议”，也可以点击“选择”后批量接受；若建议不准确，打开编辑器修改再保存。
5. Inbox 的“其他待判断”会列出当前不支持的格式和无法确定作品边界的目录。此处只显示路径、类型与大小，不能直接“接受”为媒体；Rem 不会移动它们，也不会把猜测写进 Library。已知 sidecar 和 Rem 自身文件不会出现在这里。
6. 直接接受媒体建议会保留 `filename` / `comic_info` 等自动来源，Agent 以后仍可安全更新；只有用户实际改过的字段才标记为 `manual`。`Photos/` 始终按相册媒体扫描，`Images/`、`Videos/` 是按真实目录浏览的普通分类媒体；`ImageSets/` 中的多图目录或 ZIP/CBZ 会成为漫画候选，动漫与影视视频推荐放在 `Anime/`、`Movies/`、`Series/` 或 `Works/`。旧 Library 的普通多图叶子目录仍会兼容识别为 ImageSet。
7. 在详情页编辑标题、作者、标签、Collection 和 Series。保存后这些信息写入 Library，而不是只留在手机数据库中。
8. 当前版本不在 App 内抓取站点。以后需要同步 JM、EhViewer/E-Hentai 或 Pixiv 的标题、作者和标签时，可让 Agent 先阅读 Library 根目录的 `GALLERY_LIBRARY.md` 再按来源 ID 辅助整理；Agent 只能更新未标记为 `manual` 的字段。标签采用整组字段锁定，人工改过标签后 Agent 不得擅自追加或改写。

## 阅读与播放

- “漫画 / 动漫”默认打开系列书架；可切换“全部作品”。点进系列后，详情页左右浏览范围也限制在该系列内；“单篇 / 未归系列”集中保留没有系列信息的作品。
- 编辑作品时，系列标题和手动顺序、季、集、卷、章均可独立填写或留空。手动顺序优先；未填写时按季/集或卷/章排列；完全不编号时按标题排列。编号只改变展示顺序，不会重命名或移动文件。
- 独立图片支持缩放和平移。
- 在“相册”或“图片”中打开单张媒体后，可在当前时间线内左右滑动连续浏览；双指缩放后单指用于平移，回到原始比例后恢复翻页。
- 从搜索、作者、标签或 Collection 结果打开时，左右滑动只浏览当前结果集，不会突然跳到无关媒体。
- 点按漫画先进入作品详情页，可检查封面、作者、Tag、路径和阅读进度，再选择“开始/继续阅读”；编辑不会打断列表浏览。
- 漫画/ImageSet 使用黑底沉浸式纵向连续阅读；轻触页面可呼出控件，长按当前页打开页操作侧栏，双指缩放后可单指平移，阅读位置随 Library 保存。
- 阅读器会按滑动方向预载前方 5 页、保留后方 2 页，并使用可自动清理的本机缓存；快速跳页会取消已经过时的预载任务。目录漫画按屏幕阅读所需尺寸解码，ZIP/CBZ 的已解码页面也会短期缓存。缓存可以从 Android 的应用存储设置中安全清除，不会删除 Library、标签或阅读进度。
- 目录型漫画可在阅读页打开“调整页序”：可看缩略图上/下移动，或指定目标页码。确认“保存并编号”后，底层图片按当前顺序重命名为连续页码；应用会写入可恢复事务，异常中断或下次扫描时会回滚。ZIP/CBZ 为只读，不直接改写压缩包。
- 本地视频使用 Media3 播放，退出详情页时保存播放位置。
- 相册视图混排照片、视频和已配对的 Live/Motion Photo，并优先使用 EXIF/视频拍摄时间。

## 返回与退出

- 系统返回键/返回手势与顶部返回箭头一致：先关闭右侧工具栏、对话框或选择态；阅读器返回作品详情，作品详情再返回作品列表。
- 首页第一次返回会提示“再按一次返回退出 Rem”，两秒内再次返回才退出。
- 每个 Library 的一级页面状态会分别保留；“图片 / 视频”还会分别记住上次浏览的真实目录。当前一级页面、搜索词和详情项目会在常规配置变化或系统回收进程后恢复；主动退出后仍从首页进入。

## 文件安全

- “移入回收站”只隐藏项目并写逻辑标记，不移动真实文件。
- 回收站保留原媒体缩略图（包括目录漫画封面和压缩漫画首图），方便确认后恢复；不会因为预览而恢复或改动文件。
- “永久删除”才会删除媒体；执行前会重新检查路径和内容大小。
- “整理文件”必须先生成计划。目标冲突会阻止执行；确认后会备份元数据、写事务日志、复制、校验，再删除源文件。
- 移动介质中途断开后，重新接入同一 Library 会恢复已确认但未完成的 Organizer 事务。
- “检测重复内容”只展示 SHA-256 相同的文件，不自动去重。

## 导入与派生

- “系统相册”支持 Android 的完整或部分照片授权；拒绝广泛授权后仍可使用系统选择器。
- 导入为相册媒体时保持原字节不变，并保留 `DCIM/Camera`、`Pictures/Screenshots` 等来源层级放入 `Photos/`。
- 仅选择图片或仅选择视频时，还可分别“按来源分类”导入到 `Images/` 或 `Videos/`；来源目录会成为默认的文件夹式分类视图，之后可在元数据中追加或改为虚拟 Collection，不会为了分类移动文件。
- 在系统相册按一个来源文件夹筛选后，点击“全选当前”，即可把该文件夹整组导入为图片或视频分类。
- 选择至少两张图片时可以显式导入为 ImageSet；页面按自然文件名排序复制到 `ImageSets/Imported/`。
- 系统相册导入始终复制，不移动、不删除手机相册原文件。
- 如果已经误导入为相册媒体，可在“相册”中选择图片并显式派生 ImageSet；该操作复制页面，不会删除原相册媒体。
- 详情页的复制按钮可以把照片或漫画指定页派生成普通图片。
- 图片页可选择至少两张独立图片，复制组成新的 ImageSet。
- 派生内容与来源彼此独立；删除来源不会级联删除派生项。

## 相册批量操作

- 相册使用紧凑缩略图网格。点按打开，长按任意项目先显示查看、编辑、收藏、派生、回收站和进入多选等快捷操作；也可点击“选择”直接进入多选。
- 多选后可全选、批量收藏/取消收藏、追加作者/Tag/Collection、把多张照片派生为 ImageSet，或移入逻辑回收站。
- 批量元数据是“追加”语义，不会覆盖各项目已有的作者/Tag/Collection；批量回收也不会移动或删除真实文件。

## 三个主视图

- “相册”只显示照片、相册视频与 Live/Motion Photo，按拍摄时间混排，不提供文件夹分类，也不显示作者和 Tag 筛选。
- “相册”的右侧工具栏只提供媒体类型和时间顺序；“图片 / 视频”的右侧工具栏提供当前路径、返回上级和子目录；页面工具不会混进全局左侧“库与管理”。
- “图片 / 视频”按真实文件夹显示目录封面和内容，并分别记住图片与视频所处路径。Collection 不会伪装成目录；直接修改逻辑分类不会移动底层文件。
- 同一叶子目录同时包含图片和视频时，会在“图片 / 视频 → 分组”显示为一个入口；进入后可先浏览整组图片，再播放直属视频。组内视频不会同时重复出现在独立“视频”页，嵌套子目录的视频不会被误并入。该分组只是展示关系，不移动、改名或合并文件。
- “漫画 / 动漫”包含 ImageSet 与作品视频；作者、Tag、Series、搜索和排序平时隐藏在页面右侧工具栏中。普通视频可在元数据编辑器中切换到作品库，或切回分类视频。
- 漫画的最小单位是一本 ImageSet；普通图片是单文件。两者之间通过显式派生/复制转换，互不混淆也不会自动删除来源。

扫描器兼容常见下载结构，包括“作者/NO.序号 作品名[页数-体积]/001.jpg”、漫画“系列/Chapter 01/页面”、动漫 `S01E02` 文件名以及图片目录中的附带视频。解析结果只是建议，人工元数据始终优先。

## 多 Library

可接入多个 Library，并从顶部切换。搜索默认聚合所有在线 Library；离线介质保留索引并显示离线，不会被当成已经删除。

“移除登记”需要确认，只清除本机索引并释放 Android 目录授权，不删除媒体或 `.gallery` 便携元数据。

## 诊断日志

`设置 → 诊断日志` 可以查看最近记录、导出或清除。

- 日志只保存在本机 App 私有目录，不写入 Library、不随硬盘移动，卸载应用即清除。
- 正式版默认只记录警告和错误，开发版记录全部；崩溃会自动单独落盘，下次启动仍能看到。
- 导出走系统分享，由你选择目的地；导出前账号信息、`content://` 目录 URI 和电脑盘符路径会被隐去。
- 日志按天滚动，保留 14 天、最多 10 个文件，不会无限增长。

反馈问题时，用“导出”把日志发出来即可，不需要连接电脑。

## 大容量 Library 的接入与扫描

首次接入分成“快速清点”和“媒体信息补全”两个阶段，之后是增量扫描。

- 快速清点只读目录和文件属性，不打开媒体内容、不移动媒体；完成后会先提交一个可浏览的本地索引。
- 哈希、ZIP/CBZ 页数与 ComicInfo、照片拍摄信息随后分批补全。每批完成状态保存在手机本地，应用被结束后再次打开会从剩余项目继续，而不是重读已经完成的内容。
- 再次扫描时，大小和修改时间都未变化且已经补全的文件会复用上次的指纹、页数与拍摄信息；只有变化或尚未补全的文件才会被打开。
- 目录漫画按目录指纹识别，不逐张读取图片内容。重复点击“扫描”不会并发执行两次。
- 浏览到的媒体卡片会按需保留最长边 512 px 的本机小预览。移动 Library 拔出后仍能看到这些已生成的封面；未浏览过的项目不会一次性批量生成。预览最多占用 256 MiB 或 20,000 张，可在“设置 → 离线小预览”清除，且不会删除原媒体或 `.gallery` 元数据。
- 如果应用在“快速清点”尚未首次提交前被强制停止，这一轮目录清点仍需重新开始；补全阶段已经提交的批次不会丢失。
- 接入同一个文件夹多次不会产生多份 Library 身份；如果目录里已有 `.gallery`，会直接复用其中的身份。
- `GALLERY_LIBRARY.md`、`.nomedia` 和 `.gallery/` 都是 Rem 自己的文件，第一次接入时自动生成，之后每次接入都会复用。**不需要手动删除或重建**。即使 `library.json` 被误删，重新接入也会就地恢复身份，并保留你已修改过的 `GALLERY_LIBRARY.md`。
