# Rem 使用说明

本文只描述当前版本已经可以使用的行为；未完成的计划不会提前写成可用功能。

## 接入 Library

1. 在“库与管理”中选择一个有读写权限的目录。
2. Rem 会创建 `.gallery/`、`GALLERY_LIBRARY.md`、`.nomedia` 和 Schema v4；不会改写原媒体。
3. 已有测试期 Schema v3 Library 会先把便携文档保存到 `.gallery/backups/`，再转换为 v4。更早格式不再支持；高于当前版本的格式会拒绝写入。
4. 同一目录重复接入会复用磁盘身份，不会创建多个 Library。
5. 移动介质拔出后 Library 会显示离线；重新授权同一目录即可恢复。
6. “忘记 Library”只删除本机登记、索引和 SAF 授权，不会删除盘中媒体或 `.gallery/`。

`.nomedia` 只阻止 Android 系统相册重复收录 Library 内的副本，不影响 Rem 扫描。

## 扫描和 Inbox

首次扫描分为两个阶段：

- **快速清点**：读取目录和文件信息，完成后媒体列表即可使用；
- **媒体信息补全**：分批补充哈希、ZIP/CBZ 页数、ComicInfo 和拍摄信息。

补全状态保存在手机本地。App 被结束后，下次打开会继续剩余项目。快速清点尚未首次提交时被结束，这一轮目录遍历仍需重来。

新识别媒体只出现在 Inbox，直到你接受识别建议或保存编辑。Inbox 支持单项和批量接受。

Inbox 分四个分区：

- **媒体建议**：等待确认的媒体。可以批量“接受”，也可以“忽略”；
- **其他待判断**：当前不能安全分类或打开的路径。可以标记“已处理”（确认无需 Rem 处理）或“忽略”；
- **已忽略**：被忽略的媒体和路径。它们仍在原位置，只是不再出现在普通视图；选中后可以“撤销”；
- **已处理**：已确认无需处理的待判断路径，可以“撤销”并回到“其他待判断”。

这些决定都写入 Library 的 `.gallery/state/inbox.json`，因此重建本机索引、换手机或重新接入同一目录后仍然有效：被忽略的内容不会自己回到 Inbox。撤销只删除决定，不会修改作品元数据，也不会移动或删除任何媒体。

“其他待判断”里的路径不能直接冒充可打开媒体，Rem 也不会移动它们。可以留给本地 Agent 依据 Library 根目录中的 `GALLERY_LIBRARY.md` 整理；Agent 必须保留已有决定，并把自己写的新决定标记为 `agent:<标识>`。

扫描会排除 `.gallery/`、`.nomedia`、`.ehviewer`、`ComicInfo.xml`、事务文件和已知 sidecar。

## 三个主视图

- **相册**：系统相册或导入到 `Photos/` 的图片、视频，侧重时间线。
- **图片 / 视频**：普通图片、视频、目录浏览，以及同一叶子目录中图片集和直属视频形成的混合入口。
- **漫画 / 阅读**：独立作品、系列书架和未归系列作品。

目录名只是扫描建议。人工修改的归属会写入便携元数据，并优先于以后扫描。

### 分组

“图片 / 视频”的“分组”页签显示两类内容：

- **手动分组**：已经保存到 Library 的 Group，可以打开编辑；
- **目录派生**：扫描发现“同一目录里有图片集和直属视频”，只是浏览入口，还不是你的决定。

对派生分组点“保存为 Group”，它才会变成可编辑的分组；同一个目录重复保存只会更新那一个分组，不会出现两份。

打开分组后可以：

- **添加成员**：搜索标题或路径，多选加入（成员可以是其他目录的作品）；
- **调整顺序**：长按行首的拖动手柄拖动，或用每行的上下箭头；顺序就是成员顺序；
- **设为封面**：用星标按钮选择封面成员；
- **移出成员**：只解除关系，作品本身和媒体文件都不受影响；
- **重命名 / 删除分组**：删除只删除“一起浏览”的关系。

成员、顺序和封面会先在界面上改动，点“保存”才写入 Library；分组是便携数据，换手机或重建索引后仍然存在。整个过程中 Rem 不会移动、重命名或删除任何媒体。

## 图片、漫画和视频

### 图片

- 单图支持缩放和平移；
- 未放大时左右滑动切换；
- 从搜索、作者、标签或 Collection 打开时，只在当前结果集中切换；
- GIF、Animated WebP、SVG 和系统可解码的新图片格式由现有图片组件显示；
- 超大静态图先探测尺寸并降采样。

### ImageSet 和漫画

- 目录图片按自然文件名顺序阅读；
- ZIP/CBZ 直接读取，不会解压回写；
- 阅读进度保存到便携状态；
- 连续阅读按视口解码，不会一次载入整部作品；
- 目录型 ImageSet 可以打开“调整页序”，通过缩略图移动或指定页码；
- “保存并编号”会真实重命名目录内图片，因此执行前会写入可恢复事务；ZIP/CBZ 保持只读。

### 视频

- 使用系统支持的本地播放器；
- 支持 Seek、进度保存和恢复；
- 混合组内的视频可以从统一详情页逐个播放。

## Series

漫画 / 阅读页可以在“系列书架”和“全部作品”之间切换。

编辑作品时可以填写：

- 系列标题；
- 手动顺序；
- 季与集；
- 卷与章。

这些编号都可以留空。排序优先使用手动顺序，其次是季/集或卷/章，最后按标题。没有系列的内容保留在“单篇 / 未归系列”。

进入某个系列后，右上角的“编辑系列”可以批量整理：

- **添加成员**：搜索标题、路径或作者，多选加入；
- **调整顺序**：用每行的上下箭头，或用“移动到指定序号”把作品放到第 N 位；
- **移出成员**：只解除系列关系，作品本身和媒体文件都不受影响；
- **重命名系列**：改名后成员与编号保持不变；
- **清空编号**：把季/集/卷/章一次性清空，只保留手动顺序；
- **删除系列**：只删除系列关系和编号，作品与媒体保持不变。

列表顺序就是阅读顺序；成员、顺序和编号会先在界面上改动，点“保存”才写入 Library。保存时 Rem 会把改动过的作品标记为人工系列决定，之后的扫描不会再用目录名把它们重新归类。整个过程中不会移动、重命名或删除任何媒体。

调整顺序有三种等价方式：**长按行首的拖动手柄拖动**、用每行的上下箭头、或用“移动到指定序号”。三者都只是改动界面上的顺序，点“保存”才写入 Library；成员很多（例如数百部）时用箭头或指定序号更精确。

## 多选与批量操作

“图片 / 视频”和“漫画 / 阅读”的列表右上角有“选择”，进入多选后可以：

- **加入分组**：把选中的作品一次加入某个分组（图片、视频、图集都可以）；
- **加入系列**：把选中的作品追加到某个系列；已经属于其他系列的作品会被跳过并提示数量；
- **收藏 / 批量信息 / 回收站**：批量追加作者、Tag、Collection，或一次移入逻辑回收站。

批量信息只**追加**，不会覆盖每项已有的值。所有批量操作都是对便携元数据的一次写入，不会移动、重命名或删除媒体；返回键会退出多选而不是离开页面。

## 卡片长按动作

在任意网格里长按一张卡片会打开操作面板。除了打开、接受识别建议、编辑、收藏、复制派生和移入回收站之外，作品还可以直接：

- **加入分组…**：选择已有分组，把这张卡片的作品追加为成员（已在分组中会提示，不会重复）；
- **加入系列…**：选择已有系列，把它追加到系列末尾；如果它已经属于**另一个**系列，Rem 会跳过并告诉你数量，不会擅自改动；
- **比较版本…**（图片集作品）：直接进入与另一个来源的逐页比较。

这些动作都只修改便携元数据，不会移动、重命名或删除媒体。

## 比较版本与虚拟合并

在图片集作品详情页右上角点“比较版本”，可以把它和另一个来源逐页对比：

- **快速比较**：完全不读取图片内容，只用页数、页名和每页字节大小，几秒内给出“疑似重复 / 仅一侧有”的概览；
- **深度比较**：把两个来源各读取一遍并计算每页内容哈希，给出“完全重复 / 同名但内容不同 / 仅一侧有”的确定结论；压缩包只顺序读取一次，随时可以取消。

报告会显示每个来源实际读取的字节数与耗时，方便你判断这次比较花了多少 I/O。没有读内容时，Rem 只会说“疑似重复”，不会声称两页完全一样。

确认结果后可以“生成虚拟合并版本”：在左侧作品上新增一个按合并顺序排列的版本并设为默认，阅读时按这个顺序连续读页。**两个来源的原有版本和文件都不会被修改、移动或删除**；合并的来源、深度与计数记录在 `.gallery/imports/` 中，方便以后核对。

标题相似或同作者不会自动判定为同一作品，必须由你选择要比较的两个来源。

## 元数据和人工保护

可以编辑显示标题、原标题、作者、标签、Collection、Series、归属、封面和收藏状态。

只有实际修改的字段会标记为 `manual`。以后自动识别或 Agent 同步不得覆盖这些字段。`tags` 当前按整组保护：人工改过标签后，自动流程不能追加或改写整组标签。

App 当前不抓取站点，也不保存站点账号或 Cookie。需要补全 JM、EhViewer/E-Hentai、Pixiv 等来源信息时，可以把 `GALLERY_LIBRARY.md` 交给本地 Agent。Agent 应保留稳定来源标签和所有人工字段。

## 系统相册导入

Rem 对系统相册只读浏览。导入是复制，不会移动或删除系统相册原文件。

可以：

- 复制选中的图片或视频；
- 把多张图片复制为新的 ImageSet；
- 按来源目录复制为作品；
- 保留可用的 EXIF、拍摄时间和来源目录文字；
- 处理基础 Live Photo / Motion Photo 配对。

Library 根目录的 `.nomedia` 会避免导入副本再次出现在系统相册中。

## 回收站和永久删除

普通删除只把 Work 放入逻辑回收站，媒体仍在原位置。

恢复会移除回收站记录。永久删除前 Rem 会重新定位来源并核对当前大小；文件已经变化时会停止，避免误删。

自动清理按设置的保留天数处理到期项目。建议先使用测试 Library 验证策略。

## Organizer 和真实文件变化

Organizer 是显式功能：

1. 选择模板；
2. 生成计划；
3. 查看目标路径与冲突；
4. 确认后执行；
5. 复制并验证；
6. 最后删除源并清理已确认的空目录。

执行过程记录在 `.gallery/transactions/`。移动介质中途断开后，重新接入同一 Library 会恢复未完成事务。

普通扫描、识别、改标题、切换归属、Series 和当前混合分组都不会触发 Organizer。

## 离线小预览

浏览到的媒体卡片会按需保存最长边 512 px 的本机 JPEG 预览：

- Library 拔出后仍可辨认已经生成过的卡片；
- 未浏览项目不会批量生成；
- 最多 256 MiB 或 20,000 张；
- 位于 App 私有目录，不写入移动介质；
- “设置 → 离线小预览”可以查看并清除；
- 清除预览不会删除媒体或 `.gallery/`。

SVG 和部分新图片格式可能只能在线显示，不能生成这种 JPEG 预览。

## 压缩包阅读缓存

首次打开 ZIP/CBZ 时，Rem 会把压缩包复制到系统可回收的 App 私有缓存，再通过中央目录随机读取页面。这样既能兼容部分流式读取器无法处理的压缩包布局，也不会每翻一页都重新读取整个压缩包。

- 缓存键包含 Library、相对路径、大小和修改时间，原文件变化后不会复用旧副本；
- 默认预算为 512 MiB，优先清理最久未使用的副本；单个正在打开的大压缩包可以暂时超过预算；
- “设置 → 压缩包阅读缓存”可以查看文件数和容量并立即清除；
- 缓存不写入 Library，清除不会改动 ZIP/CBZ 原文件或阅读进度。

## 搜索和批量操作

搜索可以匹配标题、作者、标签、Collection 和系列信息。相册与媒体列表支持选择模式，批量元数据修改会合并到一次便携写入；批量移入回收站也使用一次状态写入。

## 诊断日志

“设置 → 诊断日志”可以查看、导出和清除日志。日志保存在 App 私有目录，按时间和数量限制，并在写入前移除内容 URI、盘符和绝对路径。

导出问题时仍应说明：

- Library 名称；
- 相对路径；
- 操作步骤；
- 大致时间；
- 是否刚发生拔盘、授权变化或强制结束。

不要在说明中附带账号 Cookie 或 Token。

## 大容量 Library 注意事项

- 第一次清点仍可能花较长时间；
- 扫描过程中不要反复点击扫描；
- 强行停止后，已经提交的信息补全批次不会重读；
- 暂时不可读的子目录不会被当成已经删除；
- 当前构建尚未完成手机直连真实约 465 GiB E 盘的全量验收，因此看到异常耗时应导出诊断日志，而不要直接删除 `.gallery/`。
