# Rem 产品规范

本文件定义当前有效的产品目标。详细执行规则见仓库根目录 [AGENT_PRODUCT_RULES.md](../AGENT_PRODUCT_RULES.md)，写入 Library 的文件模式说明见 [AGENT_LIBRARY_RULES.md](../AGENT_LIBRARY_RULES.md)。旧的产品模型、页面流程和未重新确认的功能不再属于当前目标。

## 产品定位

Rem 是一个本地图片、漫画和视频查看工具，优先快速接入用户指定的 Library，并提供简单、可解释的浏览体验。

## 当前有效范围

- Library 根目录只允许 `相册/`、`画集/`、`待分类/`、`.gallery/`。
- `相册/` 直接存放图片和视频（保持扁平），按媒体拍摄时间排序；没有拍摄时间时使用文件修改时间。
- `画集/` 第一层使用 `作者名称-项目名称/`，其下允许任意层级的子文件夹，文件命名自由。
- `画集/` 提供可选排序：序号、名称（自然序）、拍摄时间、修改时间、文件大小，选择被记住。
- 画集同一层不混排文件夹与媒体：进入文件夹先看子文件夹，再进入下一层看媒体。
- 相册和画集均支持图片、视频混合查看或分别查看。
- 相册地点只显示媒体已有的 GPS 或地点元数据，没有证据时不显示。
- 画集支持作者名称和项目名称的最小字符串匹配。
- 长列表提供右侧拖动滑块，拖动时显示相册的时间/地点或画集的序号/名称。
- 点击媒体在 Rem 内置查看器内查看或播放，图片和视频可在**当前文件夹内**连续滑动切换；查看器始终保留「用其他应用打开」。
- 接入由用户显式选择目录触发；接入后先显示 `.gallery/` 缓存，再在后台做增量扫描；扫描按文件夹增量落盘，可中断续扫。
- `.gallery/` 按软件缓存定性：`RULES.md`、`index.json` 与缩略图缓存都由 Rem 写入，可随时删除重建；媒体文件始终只读。
- 设置里的「从系统相册隐藏」只创建或移除 Library 根目录的 `.nomedia`，用于控制后续系统媒体扫描；不修改媒体，也不清除已有系统相册记录。

## 两种工作模式

- **安卓端**：读取、排序、筛选、展示，并在内置查看器内查看和播放，同时保留调用系统查看器。除下面那个开关外，不做任何底层文件改动。
- **整理端（人或 AI）**：依据 `.gallery/RULES.md` 调整底层文件的实际存放位置和命名。`待分类/` 的归位属于这一步。

`.gallery/RULES.md` 在每次接入时被覆写为当前构建内置的版本，所以它始终描述的是运行中的这一版规则。

## 当前明确不做

当前不实现底层文件改名、移动、删除、覆盖或其他编辑；不处理 `待分类/`；不做后台全盘扫描、自动识别、自动整理、Tag、Collection、复杂 Work/Series/Edition 关系、阅读进度或复杂页面跳转，也不为不常见格式引入额外解码库。不符合目录规范的内容只报告，不自动修正。

内置查看器已于 2026-09-20 重新确认，不再属于「不做」清单；规则见 [AGENT_PRODUCT_RULES.md](../AGENT_PRODUCT_RULES.md) 第 5.1 节。

唯一允许**写入媒体目录**的是 `AGENT_PRODUCT_RULES.md` 第 9 节的 `.nomedia` 开关，它不涉及任何媒体文件；`.gallery/` 内的缓存文件不属于媒体目录，按软件缓存管理。

未来重新提出上述能力时，必须作为新的明确需求重新确认。
